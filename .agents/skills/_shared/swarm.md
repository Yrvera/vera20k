# Bounded parallel investigation

Delegate independent questions or scenarios when parallelism adds value. Use up to
three workers per wave, bounded by available host capacity; fewer is fine.
Do not pad a user's targets to fill slots. If delegation is unavailable, perform the
same bounded work serially and state the limitation.

Give each worker its target, source/worktree context, evidence standard and return
contract. Workers are read-only unless the selected leaf workflow and user authority
permit writing reports or correcting documents; assign disjoint file ownership then.
Workers never edit Rust, run Cargo, change Ghidra, write shared logs or launch more
workers. Return findings,
cited evidence, inspected coverage, unresolved questions and annotation candidates.
Workers need the applicable leaf skill; do not copy a second manual into prompts.

The parent reconciles contradictory claims, shared ownership and duplicate findings.
Recheck decisive evidence where reports disagree. Preserve explicit exhaustive scope;
report failed or uninspected targets instead of claiming a complete pass. Retry a failed
target when useful and safe; no fixed failure count requires confirmation.

The parent integrates requested reports and authorized corrections in its own worktree.
Ghidra writes follow the leaf skill's authorization and the
[Ghidra workflow](../../../docs/research/ghidra-workflow.md): all readers stop before
an authorized parent applies certain metadata serially. A generic swarm invocation
does not grant mutation authority beyond the selected workflow.
