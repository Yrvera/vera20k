## Summary

Finds a passable cell near a FootClass unit's current position and writes it into an
output buffer. The function:

1. Queries three vtable slots on `param_2` (vtable+0x2D4, +0x2D8, +0x2DC) — likely
   zone-check or neighbor-availability queries. If all three return 0, selects
   random-range variant 0; otherwise picks a random variant 1–4 via
   `Random__RandomRanged(1,4)`.
2. Calls `FUN_00501AC0` to produce a candidate destination cell based on the selected
   variant (directional scatter, forward projection, or fallback).
3. Converts the unit's lepton position (`param_2+0x9C/+0xA0`) to cell coordinates via
   sign-correct arithmetic floor shift (`(val + (val >> 31 & 0xFF)) >> 8`).
4. Calls `MapClass__GetZoneID` on the current cell to determine the unit's zone.
5. Calls `FootClass__Find_Nearby_Passable_Cell` to find a passable cell near the
   candidate destination within the same zone.
6. Writes the result packed cell coord into `*param_1`.

**Active in YR: Yes.** 4 callers: `BuildingClass__ExitObject_Main`,
`FootClass__Find_Path`, `FootClass__Mission_Rescue`, `UnitClass__PerCellProcess`.

## Behavioral Analysis

### Step 1 — Vtable queries at +0x2D4, +0x2D8, +0x2DC

Three virtual calls on `param_2` (FootClass). The exact targets depend on the vtable
installed for the concrete unit type. All three return integers; their sum controls
whether variant 0 (no scatter) or variants 1–4 (directional scatter) is used.

Known offsets from `piVar1` as `int*`:
- `piVar1[0x27]` = byte offset `0x9C` = FootClass location X (leptons)
- `piVar1[0x28]` = byte offset `0xA0` = FootClass location Y (leptons)
- `piVar1[0x29]` = byte offset `0xA4` = (possibly Z / height; passed as `iStack_4`)

The lepton-to-cell conversion applied is the standard sign-correct arithmetic floor:
```c
cell_x = (lepton_x + (lepton_x >> 31 & 0xFF)) >> 8
cell_y = (lepton_y + (lepton_y >> 31 & 0xFF)) >> 8
```
This is equivalent to `floor(lepton / 256)` with correct rounding for negative values.

### Step 3 — FUN_00501AC0: candidate destination selection

`FUN_00501AC0 @ 0x00501AC0` is a larger function (5-case switch) that picks a candidate
destination cell based on the `param_3` variant:
- Case 0: zero-radius random cell near origin (from global `DAT_00A8EFF8`)
- Cases 1–3: directional scatter with `Random__RandomRanged` distance + `Sin`/`Cos` projection
- Case 4: forward projection along current heading via `FUN_0050DF30`

This function is out of scope for this decode task but is clearly the "where should this
unit scatter to?" logic.

### Step 5 — Zone ID lookup

`MapClass__GetZoneID @ 0x0056D230` converts a cell coord to a zone ID. The result is
passed to `FootClass__Find_Nearby_Passable_Cell` to constrain the search to the same
movement zone.

### Step 6 — Find_Nearby_Passable_Cell

`FootClass__Find_Nearby_Passable_Cell @ 0x0056DC20` (documented in
`fn-find_nearby_passable_cell.md`) does the actual passability search near the candidate
cell. The result is written to `*param_1`.
