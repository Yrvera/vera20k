## Summary

A heap/vector "clear with optional free" operation. Zeros the element count field (`+0x10`), conditionally frees the backing data buffer if the ownership flag is set (`+0xD != 0`), then zeros both the ownership flag and the capacity field (`+0x8`).

This is the destructor/clear routine for the small inline-vector objects used as per-level exclusion lists in PathfinderClass (fields `+0x74`, `+0x8C`, `+0xA4`). It does NOT free or reset the struct itself — only its buffer contents.

**Proposed label:** `PathfinderHeapVec__Clear` (or `PathfinderExclusionVec__Clear`).

|---|---|---|

| `+0x08` | `int` | Capacity (number of entries allocated) |
| `+0x0D` | `char` | Ownership flag: nonzero = this struct owns the buffer and must free it |
| `+0x10` | `int` | Element count (number of valid entries) |

All offsets confirmed from decompile via `decompile_function 0x0042D540`.

### Clear sequence

1. Zero the count (`+0x10 = 0`) first — makes the vector appear empty immediately.
2. If `data_ptr != null` AND `ownership_flag != 0`: free the buffer via `FUN_007c8b3d` (runtime free, excluded per manifest), then null `data_ptr`.
3. Zero `ownership_flag` (`+0xD = 0`).
4. Zero capacity (`+0x8 = 0`).

The conditional on ownership means that if the struct was initialized with an external (non-owned) buffer, the buffer is not freed — only the count and capacity are zeroed.

### Tiberian Sun filter

`FUN_007c8b3d` is listed in the manifest as `phase0-drop: widely-called runtime utility (memset/memcpy class), not pathfinding`. The call here is a conditional buffer free. No TS-only gate — this path is reached from `PathfinderClass__Constructor` on every search init.
