# Pathfinder Zone Edge Update / Invalidation -- Ghidra Research Report

**Address(es):** `0x0042CCD0` (`PathfinderClass__UpdateHierarchicalEdges`), `0x0042CF80` (`PathfinderClass__InvalidateZoneEdge`)
**Investigation Mode:** exhaustive-slice
**Claimed Scope:** the two PathfinderClass hierarchy-edge update/invalidation functions, their immediate retry-loop caller, and the minimum helper evidence needed to explain when edge exclusions are recomputed.
**Non-Scope:** full Zone_precheck algorithm, full A* expansion, MapClass full zone rebuild, AssignOrphanedCellZone / MergeAdjacentCellZone per-cell zone repair, and full passability-matrix row semantics.
**Confidence:** High for the scoped binary behavior; Medium for Rust delta because the worktree has active edits and this pass stayed read-only.
**Active in YR:** Yes. Evidence: direct live call from `AStar_pathfind_search` at `0x0042CC79` after `AStar_main_loop` failure while hierarchical assistance remains enabled; `AStar_pathfind_search` is the normal FootClass pathfinding spine documented in prior reports and decompiled here.

## 1. Overview

`0x0042CCD0` is not a global zone-grid rebuild hook. It is a per-Pathfinder retry repair step run after a hierarchical-assisted cell A* attempt fails. It tests the current start cell's hierarchical zone at levels 0, 1, and 2, then appends packed sorted zone-pair exclusions into PathfinderClass per-level exclusion vectors.

`0x0042CF80` is the narrower invalidator used when the current zone has internally split relative to the precomputed path chain. It invalidates one edge adjacent to the current zone in the level's stored zone path and then adds second-order exclusions around the broken edge.

## 3. Core Logic

### `0x0042CCD0` -- update edge exclusions after a failed A* attempt

1. Convert `PathfinderClass+0x70` to a zone-index cell with `ZoneMap__CellToZoneIndex` (`0x0056D3F0`).
2. For `level = 0, 1, 2` only:
   - Read the current zone ID from `DAT_0087F858[cell_index * 10 + level * 2]`.
   - Allocate/reset a temporary ushort vector; the body sets its growth/capacity field to `10`.
   - Call `ZoneMap__FloodFillReachableZones` (`0x005840C0`) with the current CellClass, level, temp vector, and mover object.
3. If `FloodFillReachableZones` returns nonzero, call `0x0042CF80(this, current_zone, level)`. Active in YR: Yes; exact call is `0x0042CDAC`.
4. If it returns zero, iterate the temp vector backward. For each `neighbor_zone != current_zone`, append the sorted packed pair to the per-level exclusion vector at `+0x74 + level*0x18`.

Material details:

- Levels are fixed to exactly 3 (`level < 3` at `0x0042CE87`), not all 13 MovementZone rows. Active in YR: Yes.
- Zone-pair packing sorts endpoints before storage (`0x0042CE02..0x0042CE11`), so edge exclusions are undirected. Active in YR: Yes.
- The zero-return path uses the vector returned by `FloodFillReachableZones`, not a fresh scan of all global graph edges. Active in YR: Yes.
- This function appends to PathfinderClass-owned vectors; it does not mutate `DAT_0087F878` or `DAT_0087F858`. Active in YR: Yes.
- Temporary vector memory is freed before moving to the next level when the owned flag is set (`0x0042CE6E..0x0042CE7F`). Active in YR: Yes.

### `0x0042CF80` -- invalidate one path edge and related cross-neighbor edges

1. Read `path_len = *(this + 0xC74 + level*4)`.
2. If `path_len < 2`, set `this+0x38 = 0` and return. Active in YR: Yes; `0x0042CF94..0x0042CFA4`.
3. Search the level's `+0xBC + level*1000` u16 path for the supplied zone.
4. If the zone is absent, set `this+0x38 = 0` and return. Active in YR: Yes; `0x0042CFE0..0x0042CFF0`.
5. If found at the last path element, choose the previous edge `(path[i-1], path[i])`; otherwise choose the next edge `(path[i], path[i+1])`.
6. If endpoints differ, append the sorted packed pair to the same per-level exclusion vector via `PathfinderHeapVec__Push` (`0x0042D830`, called at `0x0042D064..0x0042D06D`) (corrected 2026-05-28: was `FUN_0042D830`; Ghidra has renamed to `PathfinderHeapVec__Push`; verified via `get_function_by_address 0x0042D830` — ROOT_CAUSE: RTTI_LABEL_DRIFT).
7. Then read both endpoint zone records from the global graph at `DAT_0087F878[level] + zone*0x24`. For every neighbor of one endpoint that also appears in the other endpoint's neighbor list, append an exclusion between the broken endpoint and the common neighbor, excluding self-pairs.

Material details:

- If the path contains only one zone, hierarchy is disabled for the retry instead of trying to invent an edge. Active in YR: Yes.
- Edge choice is asymmetric at the end of the path: last element invalidates the previous edge; all other positions invalidate the next edge. Active in YR: Yes.
- Packed edge exclusions are stored sorted and undirected in both the direct path-edge append and the common-neighbor append. Active in YR: Yes.
- Common-neighbor exclusions use the global graph as read-only source and append to PathfinderClass state; the global graph is not edited. Active in YR: Yes.
- `PathfinderHeapVec__Push` (`0x0042D830`) only appends when vector capacity/growth permits; it returns false on failed growth but callers ignore the result. Active in YR: Yes; decompiled `0x0042D830` (corrected 2026-05-28: stale name `FUN_0042D830`; Ghidra has renamed — ROOT_CAUSE: RTTI_LABEL_DRIFT).

## 6. Current Rust Implementation Status

Current Rust has a full `ZoneGrid` and a batch-oriented `zone_incremental::try_incremental_update`, but this binary slice is a different mechanism:

- `src/sim/pathfinding/zone_incremental.rs` updates persistent Rust zone maps/adjoining super-zone data after dynamic grid changes. That is closer to MapClass per-cell/full zone repair, not this PathfinderClass retry exclusion cache.
- `src/app_sim_tick.rs::rebuild_dynamic_path_grid` rebuilds `PathGrid` and then `sim.rebuild_zone_grid(grid)` after tick-level changes. This is a conservative full refresh decision, but it does not model per-search edge exclusion after an A* failure.
- `src/sim/pathfinding/zone_search.rs` uses corridor retries and zone exclusions conceptually, but the binary-specific trigger "cell A* failed, append broken zone edge(s), reset, rerun precheck" was not confirmed present in current Rust from this read-only pass.

### Negative Facts / Do Not Do

- Do not describe `0x0042CCD0` as "called after zone recomputation." Evidence: direct live caller is A* retry at `0x0042CC79`; no MapClass rebuild caller was found in the direct-call scan.
- Do not rebuild persistent Rust `ZoneGrid` as the analogue of this function. Evidence: `0x0042CCD0` and `0x0042CF80` append to PathfinderClass-local `+0x78/+0x84` vectors; global `DAT_0087F878` graph is read-only in this slice.
- Do not treat edge exclusions as directed. Evidence: both functions sort endpoints before packing.
- Do not update all 13 MovementZone categories here. Evidence: loop is exactly three hierarchy levels, `level = 0..2`.
- Do not hard-fail pathfinding when the hierarchy edge cannot be invalidated. Evidence: `+0x38` is cleared and the caller copies that into the local hierarchical flag before retry/fallback.

- Runtime frequency of the nonzero `FloodFillReachableZones` branch in common YR skirmish situations needs debugger/instrumented replay evidence.
- Direct-call scan did not prove absence of all possible indirect/control-flow entries; it did identify the live direct caller set for the scoped path.
- Rust delta should be rechecked after active worktree edits settle.
