## Summary

Vector push_back operation for the PathfinderHeapVec struct. Appends one `uint32` value (a packed zone-edge key) to the vector's data buffer. If the buffer is full (count >= capacity), attempts to grow capacity via a virtual call before appending. Returns 1 (success) or 0 (failure; capacity full and no growth).

No duplicate scan is performed before appending — this is a plain append, not a set insert.

All offsets confirmed from `decompile_function 0x0042D830` cross-referenced with `fn-fn_42dc50.md` struct layout.

### Append path (capacity not exceeded)

When `count < capacity` (normal case):
1. Read current count from `+0x10`.
2. Increment count (`+0x10 += 1`).
3. Write `*param_2` (the packed uint32 value) to `data[old_count]` at `data_ptr + old_count * 4`.
4. Return 1.

This is a pure list append with no duplicate search.

### Capacity growth path (count >= capacity)

When `count >= capacity`:
1. Checks: `ownership_flag != 0` OR `capacity == 0`, AND `growth_increment > 0` (`param_1[5] > 0`).
2. If both conditions met: calls vtable slot `+0x08` (slot 2) as `grow(growth_increment + capacity, 0)`.
   - `growth_increment` = `param_1[5]` (`+0x14`).
   - On success (returns nonzero): proceeds to append.
   - On failure: returns 0 (appended nothing).
3. If conditions not met (non-owned buffer or zero growth increment): returns 0.

### No duplicate suppression

The function checks nothing about existing entries before writing. If the same packed edge key is pushed twice, it appears twice in the buffer. This is the behavior documented in `fn-pathfinder_invalidate_zone_edge.md`: the exclusion vector is a duplicate-permitting ordered append list.
