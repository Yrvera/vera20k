# Conscript (E2)
Side: Soviet | Category: Infantry | Image alias: `Image=CONS` → `[CONS]` artmd

The Soviet basic infantry. $100 from the Soviet Barracks (NAHAND). Cheap, fast
to train, designed to be spammed in numbers. Slightly tougher than the Allied
GI counterpart (`Strength=125 vs E1's 100`, `Armor=flak vs E1's none`) but
lower DPS (M1Carbine ROF 25 vs M60 ROF 13). Cannot deploy. **Can garrison
civilian buildings** (`Occupier=yes`) — when garrisoned, swaps from
`Primary=M1Carbine` (Damage 15, Range 4) to **`OccupyWeapon=UCM1Carbine`**
(Damage 20, Range 6 — better range and damage from the building's window),
with a per-unit `OccupantAnim=UCCONS` overlay drawn at the building's window
slot. `OccupyPip=PersonRed` is the cargo pip color shown when occupying.
Country-open across all four Soviet houses (Russians, Confederation, Africans,
Arabs); no `RequiredHouses=` lock. **Trainable=yes** (default) — gains
veterancy normally.

No standalone Conscript RE doc previously existed; this document originates
the Ghidra trace of the `Occupier`/`OccupyWeapon`/`OccupantAnim`/`OccupyPip`
garrison-mode flag paths.

### Implicit defaults (not set in this section but worth noting)

- `Crawls=` — set in art section to `yes` (prone while crawling enabled)
- `Trainable=` — **not set, defaults to `yes`** — Conscripts CAN promote (presence of VeteranAbilities/EliteAbilities/ElitePrimary confirms)
- `AllowedToStartInMultiplayer=` — **not set, defaults to `yes`** — Conscript IS in the Soviet starting unit complement. This is a critical difference from most infantry (which set this to `no`). Soviet players start with several Conscripts on the map
- `LeadershipRating=` — not set; uses default (no XP-gain modifier)
- `NotHuman=` — defaults to `no`
- `ImmuneToPsionics=` — defaults to `no`; **Conscript CAN be mind-controlled** (Yuri's most common target — Conscripts are abundant)
- `ImmuneToRadiation=` — defaults to `no`; Conscripts killed by radiation
- `Bombable=` — not in explicit list (defaults to `false` for most; only E1 sets it). Crazy Ivan can still attach a bomb via Bomb mission
- `Fearless=` — not set; Conscript shows fear behavior (Panic on heavy damage)
- `Agent=`/`Infiltrate=` — not set
- `Engineer=` — not set
- `Assaulter=` — not set (cannot clear garrisoned UC buildings; only SEAL/Tanya do)
- `C4=` — not set
- `Deployer=` — not set; cannot deploy
- `DetectDisguise=` — not set
- `DefaultToGuardArea=` — not set; Conscripts hold position (MissionGuard) when idle, not GuardArea
- `Natural=` — not set
- `Cost` does not have `;` comment — straightforward
- `PreventAttackMove=` — not set, defaults to `no`; Conscript obeys Attack-Move
- `PsychicDetectionRadius=` — not set

### Referenced sequence — `[ConSequence]`

Already documented in detail in [SNIPE.md](SNIPE.md) (the SNIPE doc covers
the full `[ConSequence]` block); Conscript shares it. Summary: 20 active
slots (Ready/Guard/Prone/Walk/FireUp/FireProne/Idle1-2/Die1-5/Cheer/
Paradrop/Panic/Down/Up/Crawl), 6-direction 6-frame Walk and FireUp cycles,
Paradrop=292 single frame, Cheer=293,8,0,E. **Note `Paradrop=292,1,0` is

infantry" art layout. Per-unit `FireUp=N` (artmd top-level) varies to
match each weapon's fire timing — Conscript=6, SNIPE=5.

## Hardcoded behavior — Ghidra-verified

### 1. Garrison / Occupy mode — InfantryTypeClass-level subsystem

The `Occupier=yes` flag (InfantryTypeClass field, per
`InfantryTypeClass__ReadINI @ 0x005244D5` DATA xref to string at
`0x008259A8`) enables a multi-key subsystem:

- **`Occupier=yes`** — gates everything below; without this, the type cannot
  enter UC buildings
- **`OccupyWeapon=<weaponID>`** — weapon used while garrisoned (per
  `InfantryTypeClass__ReadINI @ 0x00524117` xref to string at `0x00825A50`).
  Default: 0 (= Primary)
- **`EliteOccupyWeapon=<weaponID>`** — Elite-tier weapon while garrisoned
  (xref to string at `0x00825A3C`)
- **`OccupyPip=<pipColor>`** — pip icon shown in the garrisoned building's
  pip strip (TechnoTypeClass field, xref to string at `0x00825A60`).
  Conscript uses `PersonRed`; GGI uses `PersonBlue`. Valid: green, yellow,
  white, red, blue, purple
- **`OccupantAnim=<animID>`** on the per-weapon side — the animation overlay
  drawn at the building's window slot when this weapon fires (WeaponTypeClass
  field, xref to string at `0x00849400`)

When a Conscript boards a UC building (Mission Enter with `Occupier=yes`),
the engine:
1. Removes the conscript from the world (Limbo-style; not the same as
   LimboLaunch — this is a permanent occupy, not a one-shot leap)
2. Increments the building's occupant counter (capped at the building's
   `MaxNumberOccupants=`)
3. Assigns the conscript's `OccupyWeapon` (or `EliteOccupyWeapon` if Elite)
   to one of the building's window-firing slots
4. Renders the `OccupantAnim` (UCCONS) at the window when firing
5. Shows `OccupyPip` (PersonRed) in the building's pip strip per occupant

The garrisoned weapons (UCM1Carbine / UCEliteM1Carbine) use the
`[InvisibleHigh]` projectile (no SubjectToCliffs / SubjectToWalls) — building
window firing passes over obstacles that ground-mode would be blocked by.
Also uses warhead `SSAB` (Soviet Small Arms Building) which has the same
Verses spread as SA but worse ProneDamage% and worse vs steel/concrete
structures — preventing garrisoned conscripts from trivializing other
structures.

### 2. OccupyWeaponRange — global garrison range modifier

INI key `OccupyWeaponRange` is a **RulesClass** field (per
`RulesClass__ReadCombatDamage @ 0x0066C6C7` DATA xref to string at
`0x0083B064`). This is a **global multiplier** applied to all
`OccupyWeapon=` weapons (not the weapon-specific Range= directly). Final
garrisoned range = `weapon.Range × OccupyWeaponRange`. Default value
typically 1.0 in stock YR. Effect: tuning all garrison weapons in one knob
without having to edit each weapon's Range.

### 3. Image=CONS redirect

INI key `Image=CONS` on the type redirects all art-lookup to the `[CONS]`
artmd section instead of `[E2]`. Standard TechnoType pattern; the `Image=`
field is read by `TechnoTypeClass__ReadINI` and stored on the type. The
short-name "CONS" matches the SHP filename on disk.

### 4. No SNIPE-style data-driven one-shot

Unlike the Sniper, Conscript has no damage-stack producing an instant-kill
effect. M1Carbine.Damage=15 × SA.Verses[none]=100% = 15 damage per shot
vs GI (100 HP) → ~7 shots to kill at ROF=25 = ~12 seconds of sustained fire.
Conscript is genuinely just a basic-DPS infantry, not a specialist.

### CRITICAL CORRECTION to audit 30 cumulative

**Audit 30 (ASW) claim: "Trainable defaults to false (ReadBool default 0)" is INCORRECT.**

Assembly-context proof at parser site 0x00714a1c:
```
00714a15: MOV CL, byte ptr [EBP + 0xc8e]   ; preload CURRENT value as default
00714a1b: PUSH ECX                          ; push current value
00714a1c: PUSH 0x843974                     ; push "Trainable" string
...
00714a24: CALL 0x005295f0                   ; ReadBool(this, sect, "Trainable", default=current_value)
00714a29: MOV byte ptr [EBP + 0xc8e], AL    ; store result
```

The ReadBool call passes `[EBP + 0xc8e]` (the existing value at the field)
as the default argument. Default is therefore **constructor-set**, not
zero. From gameplay evidence (Conscripts/Allied GI/most infantry gain
veterancy WITHOUT setting Trainable=yes), the TechnoTypeClass constructor
initializes +0xC8E = **TRUE (1)** by default.

**Correct interpretation**: most units default to Trainable=true. Units
that explicitly set Trainable=no opt OUT of veterancy. Examples of
opt-out: civilian units, engineers, possibly some structures.

**Why ASW/HORNET don't gain veterancy is NOT due to Trainable=false** —
they likely default to true. The real reason is spawn-child semantics:
SpawnManager-controlled units don't accumulate XP independently (they
inherit parent veterancy through the parent's ElitePrimary mechanism).
That's an architectural mechanism separate from the Trainable flag.

Audit 30 doc has been updated separately (this audit log + index
correction).
