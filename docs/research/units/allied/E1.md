# G.I. (E1)
Side: Allied | Category: Infantry | Image alias: `GI`

The basic Allied infantryman. $200 from the Barracks, deploy-fortifies into a
sandbag emplacement that swaps to a longer-ranged secondary weapon. IFV gunner
becomes a CRM60 long-range MG. Garrison weapon is UCPara (range 6). Three
distinct low-silhouette states exist on InfantryClass: prone-while-crawling,
deployed, and panicked — only deployed and crawling are GI-relevant in YR.

Authoritative deep RE: [GI_GHIDRA_REPORT.md](../../GI_GHIDRA_REPORT.md) (3,021 lines,
3 phases + D-T deploy follow-up — every claim cited to address).

Sequence entries are `start_frame, frame_count, facings_per_frame[, facing-mask]`.
`GI.shp` is 8-facing, so 8 facings × 6 frames = 48 frames per walk cycle (Walk
starts at frame 8, runs 6 frames per facing). `Deploy` (start 300, 15 frames,
0 facings = single-facing animation south-facing) and `Undeploy` (start 276,
2 frames, 0 facings — actually shares Up frames, which is a TS-era shortcut)
are the deploy transition animations. `Deployed` is the static deployed pose
(frame 292, 1 frame, 1 facing). `DeployedFire` plays starting frame 315 for
6 frames during firing while deployed.

> **Quirk** noted in the Ghidra report: `Undeploy=276,2,2` reuses the `Up`
> frames rather than playing a dedicated reverse-deploy animation. The
> deployed-state visual flip (sandbag piling) happens via the `Deploy`
> animation only on entry; exit just plays the brief stand-up transition.

### Warhead blocks

```ini
[SA]
Verses=100%,80%,80%,50%,25%,25%,75%,50%,25%,100%,100%
InfDeath=1
AnimList=PIFFPIFF,PIFFPIFF
Bullets=yes
ProneDamage=70%

[SSA]
Verses=100%,100%,100%,60%,40%,40%,75%,50%,25%,100%,100%
InfDeath=1
AnimList=PIFFPIFF,PIFFPIFF
Bullets=yes
ProneDamage=80%

[SSAB]
Verses=100%,80%,80%,50%,25%,25%,75%,30%,20%,100%,100%
InfDeath=1
AnimList=PIFFPIFF,PIFFPIFF
Bullets=yes
ProneDamage=50%
```

`Verses=` columns map to armor types in this order: none, flak, plate, light,
medium, heavy, wood, steel, concrete, special_1, special_2. The eleven values
match `[General] Armor=` ordering.

- `SA`: anti-infantry only; cuts to 25% vs medium/heavy armor and concrete.
- `SSA`: stronger vs flak/plate (100% vs 80%) — used by deployed Para; higher
  prone damage (80% vs SA's 70%) makes deployed GIs effective vs crawling
  prone infantry.
- `SSAB`: anti-building bias — `Verses=` is mid-tier but `Bullets=yes` plus
  the `ProneDamage=50%` quirk balances out. The "B" suffix means the warhead
  is the building-attack variant (Verses column 7 = steel = 30%, column 8 =
  concrete = 20%, columns 6/7 picked for window-fire balance).
- `InfDeath=1` selects death animation pool (`1` = generic bullet death).
- `AnimList=PIFFPIFF,PIFFPIFF` — small impact dust puff (one or two random).
- `Bullets=yes` — counted as bullet damage for game-stat purposes; affects
  some legacy armor reaction code.
- `ProneDamage=` — multiplier when the target is in prone-while-crawling
  state (`InfantryClass+0x6DB` = 1).

## Prerequisites, owners, tech

- `Prerequisite=GAPILE` — Allied Barracks must be built and present.
- `Owner=British,French,Germans,Americans,Alliance` — all four Allied
  subfactions plus the generic `Alliance` AI placeholder. Soviet/Yuri houses
  cannot build the GI.

- `ForbiddenHouses=` / `RequiredHouses=` not set.

`[AI]` rules sections (not unit data).

## Veterancy and upgrades

- **Rookie** (default): Primary `M60`, Secondary `Para`, OccupyWeapon `UCPara`.
- **Veteran** (`VeteranAbilities=STRONGER,FIREPOWER,ROF,SIGHT,FASTER`):
  - `STRONGER` = +50% effective HP (per `[General]` veteran multipliers)
  - `FIREPOWER` = +25% damage
  - `ROF` = -25% reload time (faster fire)
  - `SIGHT` = +1 cell sight radius
  - `FASTER` = +10% movement speed
  Weapons unchanged at veteran rank.
- **Elite** (`EliteAbilities=SELF_HEAL,STRONGER,FIREPOWER,ROF`):
  - `SELF_HEAL` = passively regenerate 1 HP per `[General] SelfHealInfantry`
    interval (~ every 25 frames at full health regen cadence)
  - Plus another `STRONGER`/`FIREPOWER`/`ROF` step cumulative with veteran
  - **Primary swap**: `M60` → `M60E` (15 → 25 damage)
  - **Secondary swap**: `Para` → `ParaE` (25 dmg, range 5 → 6)
  - **OccupyWeapon swap**: `UCPara` → `UCElitePara` (30 → 40 damage)
  - Cameo swaps to `AltCameo=GIUICO`

GI does not have a `Crusher=` / `Crushable=no` progression — crushable at all
ranks.

## Hardcoded behavior in gamemd.exe (Ghidra-verified)

The full RE is in [GI_GHIDRA_REPORT.md](../../GI_GHIDRA_REPORT.md); this section
extracts the unit-defining hardcoded paths. Confidence axes follow the project
convention (content / identity / binding).

### Deploy / fortify cycle

- **Sequence transitions** — `InfantryClass::DoType_Sequencer @ 0x00520A60`
  is the claim in the GI report. **[INCORRECT — see audit log iter 1]**:
  there is **no standalone function** at 0x00520A60. The address falls inside
  `InfantryClass::Fire_At_Target` (body `0x005206b0–0x00520ade`). The real
  mechanism: sequence transitions happen via `vtable+0x558` vfunc calls from
  inside `Fire_At_Target`. The "DoType_Sequencer" name appears to refer to
  the vtable slot at offset +0x558, not a separate function entry point.
  **[BINARY-VERIFIED]** sequence-id check at LAB_0052083e:
  `if ((iVar3 == 0x1b) || (iVar3 == 0x1c) || (iVar3 == 0x1d) || (iVar3 == 0x1e))`
  → calls `vtable+0x558(0x1d, 0)` (DeployedFire transition).
  Sequence ids 0x1B–0x1F are the deploy state machine:
  - 0x1B = Deploy (transition into deployed; sets entity `+0x2A4` = 1 →
    `IsLowSilhouette`; plays `DeploySound`)
  - 0x1C = Deployed (idle deployed pose)
  - 0x1D = DeployedFire (firing-while-deployed body cycle)
  - 0x1E = DeployedIdle (variant idle while deployed)
  - 0x1F = Undeploy (clears `+0x2A4`; plays `UndeploySound`)
- **DeployFire weapon swap** — when `TechnoTypeClass+0x6AC` (`DeployFire=`) is
  true and the body is in sequence 0x1C/0x1D, `Fire_At_Target` selects weapon
  slot `+0x6A8` (`DeployFireWeapon=`, default 1 = Secondary). For E1 this
  means M60 standing → Para deployed (D-T.4 in the GI report; HIGH content +
  HIGH identity + HIGH binding).
- **Player-input trigger** — Q-deploy hotkey or right-click deploy command
  routes through `EventClass::Process` mission-change-to-Unload (mission 9),
  which on infantry with `Deployer=yes` (`InfantryTypeClass+0xEC8`) calls into
  `DoType_Sequencer(0x1B)` (D-T.1 in the report).
- **Auto-undeploy on move/IFV-load** — D-T.2 / D-T.8: if a deployed GI gets a
  Move order, the AI dispatcher forces sequence 0x1F before accepting
  navcom. Boarding an IFV also forces undeploy (passenger-loading code path
  cannot accept a low-silhouette body).

### Garrison

- `Occupier=yes` (`InfantryTypeClass+0xEB4`) **[BINARY-VERIFIED iter 1]** gates the
  right-click-into-civilian-building cursor. Confirmed offset from
  `BuildingClass::AddGarrisonOccupant @ 0x00522910` decompile: first instruction
  reads `*(char *)(building_type_ptr + 0xeb4)`, which is the Occupier flag on
  the infantry's type. Adjacent offset `+0xeb5` is a related flag (JumpJet/
  paratrooper-occupier — triggers `SpawnUnitsWithParachute`).
- On entry, `BuildingClass::AddGarrisonOccupant` (0x00522910, §P2.14)
  **[BINARY-VERIFIED iter 1 — function exists at that exact address, body
  0x00522910–0x00522a4d]** attaches the infantry to the building's occupant
  list and replaces its weapon with `OccupyWeapon` (or `EliteOccupyWeapon` at
  Elite rank). Field offsets seen in decompile: `param_2[0x1a3]` (max occupants),
  `param_2[0x1a5]` (current occupant count, incremented and stored), `param_2[0x1a6]`
  (extra capacity?). Weapon swap to `OccupyWeapon` happens via vtable+0x1bc
  call → `FUN_0070f6e0`. EVA notification "structure occupied" plays at
  `param_2[0x1a5] == 1` (first occupant only).
- The garrison weapon `UCPara` uses `InvisibleHigh` projectile (no wall block)
  and warhead `SSAB` (anti-building bias) — building output is intentionally
  better than the deployed-Para output.

### IFV gunner

- `IFVMode=2` (TechnoTypeClass `+0x688`) **[INFERRED — offset not re-verified
  in iter 1 audit; struct claim deferred to a deeper audit pass]** is the
  index into the IFV's gunner weapon table — when an E1 boards an `HTK`, the
  IFV swaps to its Weapon3 slot (CRM60).
- `TechnoClass::SetGunnerWeapon` @ 0x0070DC70 **[BINARY-VERIFIED iter 1 — exact
  address, body 0x0070dc70–0x0070dcdd]** reads the passenger's IFVMode and
  reconfigures the IFV. Decompile-verified behavior: takes `(this, gunner_index)`,
  bounds-checks `0 ≤ gunner_index < 0x12` (18 max gunner slots), writes
  `this[0x4e] = gunner_index` (offset 0x138 — current gunner index) and
  `this[0x49] = weapon_ptr` (offset 0x124 — resolved weapon pointer via
  `FUN_007178b0`). Early-out at `iVar1+0x810 != 0` gates on some IFV-state
  flag. See [IFV_AND_OPEN_TOPPED_TRANSPORT_GHIDRA_REPORT.md](../../IFV_AND_OPEN_TOPPED_TRANSPORT_GHIDRA_REPORT.md)
  for the full chain.

### Battle Fortress (`OpenTransportWeapon=1`)

- When the GI is a passenger in the Battle Fortress (FV) or a Tank Bunker, the
  open-topped transport fire path reads `OpenTransportWeapon=` and picks the
  Secondary slot (value `1` = Para). Unlike IFV the FV does not swap its own
  weapons — each passenger fires their own selected slot from the FV's
  gun-mount FLH (§P2.13 / §3.5).

### Mind-control / Iron Curtain / Crush

- `ImmuneToPsionics=no` → eligible for `CaptureManagerClass::CaptureUnit`
  (0x00471D40, §P3.3) **[BINARY-VERIFIED iter 1 — exact address, body

## TS-legacy filter

The following keys on `[E1]` are TS holdovers, inactive or trivially-applied in YR:

- `ImmuneToVeins=yes` — Veins are TS terrain (the corrupting vine cells). YR
  has no vein cells, so this flag is set defensively but never evaluated in
  a YR skirmish. The vein-damage code paths exist in gamemd.exe but their
  callers are dead. Safe to leave at the default true and not implement
  vein damage at all in the Rust port.
- `Locomotor={4A582744-9839-11d1-B709-00A024DDAFD1}` — the GUID points to the
  TS-era `WalkLocomotionClass`. Live in YR (every infantry uses it). Not dead.
- `Crawls=yes` (art) — sets `InfantryTypeClass+0xEBD`. Live in YR — drives
  the prone-while-walking sequence-switch.
- `Cyborg=` / `NotHuman=` / `DetectionDistance=` / `HarvestRate=` (parse
  targets in `InfantryTypeClass+0xEAC..0xEB8`) — TS legacy keys not set on E1;
  parser still reads them and they default to false/0. No-op for E1.
- Sequence `Undeploy=276,2,2` reuses the `Up` (276) frames — this is a TS-era
  asset-reuse shortcut. Live in YR, just frame-shared. Not dead.
- `Panic=8,6,6` reuses the `Walk` frames — likewise frame-shared, live in YR.

No keys on E1 require **gating** behind `SpecialFlags`. None of E1's behavior
depends on `MultiplayerDialogSettings.FogOfWar` or other YR-disabled defaults.

### Key behavioral findings (decompile-verified)

1. **Deploy state machine** (from Fire_At_Target decompile):
   - Sequence-id check at `LAB_0052083e`:
     ```c
     iVar3 = *(int *)&param_1[1].field_0x1a4;
     if (((iVar3 == 0x1b) || (iVar3 == 0x1c)) ||
         ((iVar3 == 0x1d) || (iVar3 == 0x1e))) {
       (**(code **)(param_1->vtable + 0x558))(0x1d, 0);
     }
     ```
   - **VERIFIED**: deployed states are sequence IDs `0x1b/0x1c/0x1d/0x1e`.
   - **VERIFIED**: transitions are vtable calls at `+0x558` — likely the
     `DoType_Sequencer` vfunc the doc named.
   - **`param_1[1].field_0x1a4`** is the current sequence-id field on InfantryClass.

2. **Weapon-slot offsets on InfantryTypeClass** (visible in Fire_At_Target):
   - `+0xE40` — primary weapon ptr
   - `+0xE44` — elite primary weapon ptr (when `param_1[1].field_0x1bb != '\0'` = is-elite)
   - `+0xE48` — secondary weapon ptr (selected when `+0x5a4 != 0` condition met — likely `DeployFire`)
   - `+0xE4C` — elite secondary weapon ptr (selected when `+0x5c8 != 0` condition met — likely Elite-DeployFire)
   - `+0x5a4` / `+0x5c8` are flags on **WeaponTypeClass** (the resolved weapon), not InfantryTypeClass — the conditions are weapon-property checks.
   - This **partially refines** the doc's claim that `DeployFire` is at `TechnoTypeClass+0x6AC`. The selection logic at runtime reads `+0xE40/+0xE48` on InfantryTypeClass directly; the cheat-sheet's `0x00843aa0 → 0x007147ef` xref for the field name is the INI **parse** offset, not the runtime read offset. **Both can be correct** — at parse time, the field is read into the type struct, then at runtime the offsets `+0xE40/+0xE48` are read. The doc's `+0x6AC` claim is unverified in this audit and may refer to a different struct layout (TechnoType base vs InfantryType extension).

3. **Garrison occupant fields** (from AddGarrisonOccupant decompile):
   - `*(char *)(building_type + 0xeb4)` — **`Occupier` flag**. **VERIFIED offset.**
   - `*(char *)(building_type + 0xeb5)` — adjacent flag, triggers `SpawnUnitsWithParachute` (paratrooper-occupier).
   - `param_2[0x1a3]` (offset 0x68c) — max occupants count.
   - `param_2[0x1a5]` (offset 0x694) — current occupant count (incremented).
   - `param_2[0x1a6]` (offset 0x698) — additional occupant capacity.
   - Weapon swap happens via vtable+0x1bc → `FUN_0070f6e0`.
   - EVA notification "structure occupied" plays at `param_2[0x1a5] == 1` (only on first occupant).

4. **IronCurtain function is a thin wrapper** (from decompile):
   - Body is only 0x3b bytes (extremely short).
   - Reads `*(undefined4 *)(type + 0xa0)` (display-name pointer?) and forwards to `vtable+0x16c` with `g_RulesClass_Instance + 0xfa8` (IC duration from Rules).
   - The "invuln frame counter / visual remap" claim in the doc happens **inside vtable+0x16c**, not in this function. Marked INFERRED.

5. **SetGunnerWeapon** (from decompile):
   - Field offsets: `this[0x4e]` (= byte offset 0x138) stores gunner index; `this[0x49]` (= byte 0x124) stores resolved weapon pointer.
   - Bounds: `0 ≤ gunner_index < 0x12` (max 18 IFV gunner slots — engine cap).
   - Gated on `iVar1+0x810` flag (likely "IsGattling" on the IFV type — Gattling weapons skip gunner swap).

### Discrepancies resolved

- **`InfantryClass::DoType_Sequencer @ 0x00520A60`** is **NOT** a standalone function. The deploy sequence transitions in `Fire_At_Target` use `vtable+0x558` vfunc calls. The "DoType_Sequencer" name probably refers to that vfunc slot.
- **`Fear_Decay_Handler @ 0x00518C00`** is Ghidra-labeled `InfantryClass::SetFear`. Same function, different name. The original doc's name appears to be a guess based on what the function does conceptually, not the canonical Ghidra label.

- **`TechnoTypeClass+0x688 = IFVMode` offset claim** — deferred. The Fire_At_Target decompile doesn't show this offset directly; needs separate trace into TechnoTypeClass__ReadINI parsing.
- **`TechnoTypeClass+0x6AC = DeployFire` / `+0x6A8 = DeployFireWeapon` offsets** — deferred. The runtime read uses `InfantryTypeClass+0xE40/+0xE48` (verified). The parse-time offsets are different and not traced this pass.
- **`InfantryClass+0x2A4 = IsLowSilhouette`** — deferred. Crush logic in OnEnterCell_Triggers not decompiled.
- **Self-heal / veterancy promotion / cloning vat duplication paths** — deferred. Not on the critical-claim path for E1 specifically.
- **No `if (type == E1)` branch** claim — re-checking string search:
  - `search_strings "E1"` and `search_strings "GI"` return 100+ substring matches.
  - Original doc's claim that no GI-specific branch exists is plausible (the flag-driven design is consistent with what Fire_At_Target shows — generic Deployer/DeployFire/Occupier reads), but NOT positively proved by exhaustion search. **Marked INFERRED.**

### Confidence summary
