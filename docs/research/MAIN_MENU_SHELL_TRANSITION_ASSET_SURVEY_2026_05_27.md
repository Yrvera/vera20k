## 1. Overview

The nice effect is mostly pre-rendered SHP animation frames, not true geometry movement. Existing reports show `FUN_006071E0` advances frame indices on shell/right-panel shapes at 30 ms ticks, staggered by child/control slot, which makes a wave-like "slide" illusion.

The standard initial main menu dialog `0xE2` does not run a native between-page slide when a right-column button is clicked. Its visible click feedback is immediate button-state art and sound; any later smooth page appearance belongs to a downstream shell dialog or to Rust's current direct bridge.

## 3. Mechanism Summary From Existing Reports

`FUN_006071E0` is a temporary shell transition/redraw helper. It does not move windows or linearly translate sprites. It enumerates child shell controls, builds a stagger schedule, then redraws shape frames every `Sleep(0x1E)` = 30 ms.

For the generic transition, regular button cells use `SDBTNANM.SHP` transition frames. The current best report says show direction cycles per-cell frames `10 -> 5` over six steps and then settles to frame `1`; close direction cycles `5 -> 10` and settles to `10`. `SDMPBTN.SHP` and `SDWRNTMP.SHP` have their own 0..5 transition frame groups behind dialog-record flag gates.

## 4. Direct Main Menu Caveat

For standard initial main menu dialog `0xE2`, `SHELL_TRANSITION_ON_MAIN_MENU_CLICK_GHIDRA_REPORT.md` verifies the slide gate byte is never set, so `FUN_00608070` bails during cleanup and the main-menu dialog is destroyed without this helper running. Do not implement a native main-menu slide-out solely from the user's perception.

The player can still perceive animation because the button snaps to pressed art, the click sound fires, the movie panel continues briefly, and the next shell page may run its own intro/reveal.
