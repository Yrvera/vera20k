## Summary

Persistent building damage fires are stored as eight raw `AnimClass*` slots at `BuildingClass+0x5C8..+0x5E4`. They are cleared as a whole group, not individually replaced. The normal repair/threshold recovery path is the early damage-fire phase in `BuildingClass::Update`: when the cached damaged byte `+0x5E8` changes from true to false, the game loops all eight slots, calls each non-null anim's vtable `+0xF8`, writes the slot to null, and then writes `+0x5E8 = 0`.

The same eight-slot clear loop appears redundantly in zero-health `BuildingClass::Update`, `BuildingClass::DestructionEffects`, `BuildingClass::Limbo`, `BuildingClass::Sell` state 0, and `BuildingClass::Destructor`. Those repeated clear loops are idempotent because each one nulls the slot after `+0xF8`.

Damage-fire anims are not attached to the building via `AnimClass::SetOwnerObject`. `CreateDamageFireAnims` constructs them at already-computed world coordinates with `drawFlags=0x600`, stores the pointer in the building slot, and does not call `SetOwnerObject`. The `SetOwnerObject` xref list has no `0x0043C0D0` caller. `BuildingClass::ChangeOwner` does not clear, re-own, or transfer damage-fire slots.

## Lifecycle Matrix

| Scenario | Native behavior | Active in YR |
|---|---|---|
| Health recovers above selected threshold before building update | Early damage-fire phase clears all 8 slots and writes `+0x5E8=0`. | Yes |
| Repair AI raises health above threshold during the same `Update` | No immediate clear in the already-passed damage-fire phase; next update sees the recovered health and clears. | Yes |
| Health remains below/equal selected threshold | Slots persist; no respawn/replacement while `+0x5E8` remains true. | Yes |
| A slot is occupied and creation is attempted | Creation returns at first occupied slot; no replacement and no later-slot fill. | Yes |
| Building reaches zero health and continues through zero-health update branch | All slots clear before destruction timer/destruction effects/survivor/uninit path. | Conditional |
| Destruction effects run directly or through vtable `+0xD4` death path | First operation clears all damage-fire slots. | Yes |
| Player sell, sell state 0 | Clears all slots before setting sell state to 1. | Yes |
| Building `ObjectClass::UnInit` | Calls virtual `+0xD4`; building vtable resolves to `BuildingClass::Limbo`, which clears slots if not already in limbo. | Yes |
| Building `Limbo`/conceal while already in limbo or Type null | The guarded clear block is skipped. Destructor has a later direct clear fallback. | Conditional |

## Negative Facts / Do Not Do

- Do not replace an occupied damage-fire slot or fill later empty slots after the first occupied slot. Native `CreateDamageFireAnims` returns immediately. Active in YR: Yes.
- Do not treat `drawFlags=0x600` as proof of `SetOwnerObject` attachment. Damage-fire creation has no `SetOwnerObject` call. Active in YR: Yes.
- Do not clear damage fires in `BuildingClass::ChangeOwner`; native owner transfer leaves the slot pointers alone. Active in YR: Yes.
- Do not rely on generic base `ObjectClass::Conceal` alone to clear building damage-fire slots; the building-specific `Limbo`/destructor paths own the slot clear. Active in YR: Conditional on dispatch path.
- Do not simply drop render overlays on cleanup once generic AnimClass exists; native calls each anim's `+0xF8`, which can release sound, detach owner if any, conceal/unregister, and queue pending delete. Active in YR: Yes.

## Remaining Uncertainty

- Direct non-virtual calls to base `ObjectClass::Conceal @ 0x005F4D30` on a `BuildingClass*` were not exhaustively censused. Normal building uninit/conceal dispatch uses virtual `+0xD4 -> BuildingClass::Limbo`, which was verified.
- No live debugger pointer sample was taken to show concrete slot values before/after cleanup; static decompile and xrefs prove the writes/calls.
- Exact audible timing of `StopSound` for damage-fire anim cleanup depends on each fire `AnimType` and generic `AnimClass::Destroy`; this report proves cleanup calls `+0xF8`, not the downstream mixer timing.
